요청하신 Golden Master 기준 파일과 생성 스크립트를 현재 C++/CMake/Catch2 구조에 맞춰 추가하겠습니다. 먼저 `UnitConverter` 실행 방식과 기존 테스트/빌드 패턴을 확인하겠습니다.

기존 테스트는 `UnitConverter.cpp`를 직접 include하는 Catch2 방식이고, 실행 파일 출력도 이미 빌드 산출물로 존재합니다. 이제 출력 포맷과 CMake 테스트 등록 방식을 확인한 뒤 Golden Master 테스트와 스크립트를 붙이겠습니다.

현재 `main()`은 프롬프트도 stdout에 쓰고, `formatPlain()`은 기본 스트림 정밀도를 사용합니다. 요청하신 기준 파일 예시가 소수점 6자리 문자열 비교를 전제로 하므로, 출력 포맷을 고정 정밀도로 맞추고 그 출력을 기준 파일/테스트/생성 스크립트가 공유하도록 하겠습니다.

파일 편집을 시작합니다. `formatPlain()`은 변환 결과값만 6자리 고정 소수점으로 출력하게 하고, 프롬프트는 Golden Master stdout을 오염시키지 않도록 stderr로 옮기겠습니다.

Golden Master는 실행 파일을 시나리오별로 한 번씩 호출해 섹션 형태로 합성하도록 만들겠습니다. 테스트도 같은 섹션 합성 로직을 사용해 기준 파일이 없으면 생성하고, 있으면 문자열 비교와 간단 diff를 출력하게 추가합니다.

이제 CMake를 다시 구성/빌드한 뒤 생성 스크립트로 기준 파일을 만들겠습니다. 스크립트는 기본적으로 `tests/golden_master_expected.txt`를 생성하고 해당 파일만 `git add`까지 수행합니다.

빌드 중 Catch2 번들 헤더가 `INFO`/`SUCCEED` 매크로를 제공하지 않는 구성이어서 Golden Master 테스트를 기존 테스트에서 이미 쓰는 `FAIL`/`REQUIRE` 스타일로 맞추겠습니다.

생성된 기준 파일에서 같은 시나리오의 두 번째 줄부터 source 값에도 `fixed` 조작자가 남는 문제가 보였습니다. 줄마다 source는 기본 표현, 변환값은 6자리 고정 표현이 되도록 포맷을 바로잡고 다시 생성하겠습니다.

기준 파일이 요청하신 섹션 구조로 생성됐고 `git add`도 스크립트가 수행했습니다. 마지막으로 CTest와 관련 파일 상태를 확인하겠습니다.

첫 CTest 실행은 Visual Studio 다중 구성 빌드라 `-C Debug`가 필요해서 테스트가 실행되지 않았습니다. 같은 빌드 산출물로 Debug 구성을 지정해 다시 실행합니다.

Golden Master 테스트의 실행 파일 호출은 Windows `cmd /C`가 따옴표와 리디렉션을 해석하는 방식 때문에 실패했습니다. 테스트 내부 명령을 Windows 전용 `cmd.exe /D /C ""exe" < "input" > "actual""` 형태로 고치겠습니다.

완료했습니다. `tests/golden_master_expected.txt`를 생성했고, 요청대로 해당 파일은 `git add tests/golden_master_expected.txt` 상태입니다. 생성 스크립트는 `scripts/generate_golden_master.ps1`입니다.

`tests/golden_master_expected.txt` 내용:

```text
[meter:2.5]
2.5 meter = 8.202100 feet
2.5 meter = 2.734025 yard
---
[feet:1.0]
1 feet = 0.304800 meter
1 feet = 0.333332 yard
---
[yard:1.0]
1 yard = 3.000009 feet
1 yard = 0.914403 meter
---
[meter:0.0]
0 meter = 0.000000 feet
0 meter = 0.000000 yard
```

추가로 `tests/test_golden_master.cpp`에 approve 패턴을 넣었습니다. 기준 파일이 없으면 현재 stdout으로 자동 생성하고, 있으면 문자열 비교 후 불일치 라인의 diff를 출력하며 FAIL합니다.

생성 스크립트 실행:

```powershell

```

말씀하신 의도에 맞게 테스트 코드를 “현재 출력(actual)을 만들고, 기준 파일(expected)을 읽어서 문자열 그대로 비교하는 approve 흐름”이 드러나도록 재작성하겠습니다. 먼저 현재 `test_golden_master.cpp`를 확인한 뒤 구조를 명확히 바꾸겠습니다.

현재 구현도 비교는 하고 있었지만, approve 단계가 테스트 본문에 흩어져 있어 의도가 잘 드러나지 않았습니다. `approveGoldenMaster(expectedPath, actual)` 함수로 분리해서 “없으면 approve(생성), 있으면 actual vs expected 문자열 비교, diff 출력 후 FAIL” 흐름이 명시적으로 보이게 바꾸겠습니다.

테스트 본문은 이제 `actual` 생성과 `approveGoldenMaster(expectedPath, actual)` 호출만 남도록 정리했습니다. 빌드와 Golden Master 테스트를 다시 실행해 확인하겠습니다.

반영했습니다. `tests/test_golden_master.cpp`를 approve 패턴이 명확히 드러나도록 재작성했습니다.

핵심 흐름은 이제 이렇게 분리되어 있습니다.

```cpp
const std::string actual = buildActualGoldenMaster();
approveGoldenMaster(expectedPath, actual);
```

`approveGoldenMaster()` 동작:

- `tests/golden_master_expected.txt`가 없으면 현재 `actual` 출력으로 자동 생성
- 있으면 `expected = readFile(expectedPath)` 후 `actual != expected` 문자열 비교
- 불일치 시 `makeDiff(expected, actual)`를 `stderr`로 출력하고 테스트 FAIL

검증도 완료했습니다.


요건에 맞춰 Golden Master 테스트를 케이스별 비교 방식으로 다시 구성하겠습니다. 프로젝트는 Catch2 기반이라 `TEST_F`/`EXPECT_EQ` 형태는 Catch2 위에 얇은 호환 매크로로 표현하고, 실제 비교는 기준 파일의 섹션 문자열과 stdout 캡처 문자열을 직접 비교하도록 바꾸겠습니다.

현재 파일은 전체 Golden Master 합본 하나를 비교하고 있어서, 요청하신 GM-TC-01~04 개별 섹션 비교와 맞지 않습니다. `golden_master_expected.txt`의 `[scenario]` 섹션을 읽어 각 테스트가 자기 stdout만 비교하도록 갈아엎겠습니다.

`test_golden_master.cpp`를 4개 테스트 케이스로 분리했고, 각 테스트가 기준 파일의 해당 섹션만 읽어서 `actual.txt` 캡처 결과와 `EXPECT_EQ(expected, actual)` 형태로 비교하게 했습니다. 이어서 CMake 타깃/테스트 이름을 요청하신 `UnitConverter_test`와 `GoldenMaster`로 맞추겠습니다.

재작성 완료했습니다. `tests/test_golden_master.cpp`는 이제 4개 Golden Master 케이스를 각각 테스트하며, 각 케이스는 `UnitConverter < input.txt > actual.txt` 방식으로 stdout을 캡처한 뒤 `golden_master_expected.txt`의 해당 섹션과 문자열 비교합니다.

적용된 테스트 마킹:

```cpp
TEST_F(GoldenMasterTest, UnitConverter_meter_2_5)
TEST_F(GoldenMasterTest, UnitConverter_feet_1_0)
TEST_F(GoldenMasterTest, UnitConverter_yard_1_0)
TEST_F(GoldenMasterTest, UnitConverter_meter_0_0)
```

비교 흐름:

```cpp
const std::string expected = expectedSectionForScenario(scenario);
const std::string actual = captureStdoutForScenario(testCaseId, scenario);

if (actual != expected) {
    std::cerr << makeUnifiedDiff(expected, actual);
}

EXPECT_EQ(expected, actual);
```

실패 시 출력 형식도 반영했습니다.

```text
--- expected
+++ actual
@@ line-by-line diff @@
```

`CMakeLists.txt`도 요청 형태로 변경했습니다.

```cmake
add_executable(UnitConverter_test tests/test_golden_master.cpp)
add_test(NAME GoldenMaster COMMAND UnitConverter_test)
```

ApprovalTests.cpp 기반으로 바꾸려면 현재 프로젝트에 라이브러리가 있는지와 CMake에서 가져오는 방식을 먼저 확인하겠습니다. 이어서 공식 사용법을 확인해 Catch2 연동 방식에 맞춰 테스트를 다시 작성하겠습니다.

Context7 문서 조회는 할당량 초과로 실패해서, 현재 저장소 상태와 ApprovalTests.cpp의 일반적인 Catch2 연동 방식으로 진행하겠습니다. CMake에서는 ApprovalTests.cpp를 FetchContent로 가져오고, 테스트는 `Approvals::verify(...)`를 호출하는 형태로 바꾸겠습니다.

파일 편집을 시작합니다. 수동 expected 섹션 파서와 자체 diff 코드를 제거하고, ApprovalTests.cpp가 `.approved.txt` / `.received.txt`를 관리하도록 테스트를 바꾸겠습니다. CMake도 ApprovalTests.cpp를 FetchContent로 가져와 `ApprovalTests::ApprovalTests`에 링크하도록 수정합니다.

ApprovalTests.cpp 의존성 연결까지 반영했습니다. 이제 CMake 구성/빌드 결과를 확인하고, ApprovalTests가 요구하는 `.approved.txt` 기준 파일명을 확인한 뒤 기존 Golden Master 내용으로 승인 파일을 생성하겠습니다.

빌드가 ApprovalTests.cpp 내부 Catch2 연동 헤더에서 `catch2/catch.hpp`를 찾지 못해 멈췄습니다. ApprovalTests가 내려받은 Catch2 어댑터 헤더 위치를 확인해서 include path를 보정하겠습니다.

빌드는 통과했습니다. 이제 ApprovalTests가 생성하는 received 파일명을 확인하기 위해 GoldenMaster 테스트를 실행하고, 기존 기준 출력으로 approved 파일을 채우겠습니다.

ApprovalTests.cpp가 예상한 승인 파일 경로가 확인됐습니다. `tests/approval_tests/*.approved.txt` 네 파일을 기존 기준 섹션 내용으로 추가하겠습니다.

ApprovalTests.cpp 적용해서 다시 작성했습니다.

변경 내용:
- `tests/test_golden_master.cpp`에서 수동 expected 섹션 파싱/diff/`EXPECT_EQ` 비교 제거
- `#define APPROVALS_CATCH` + `ApprovalTests.hpp` 기반으로 변경
- 각 케이스는 여전히 `UnitConverter < input.txt > actual.txt` 방식으로 stdout 캡처
- 캡처된 문자열을 `ApprovalTests::Approvals::verify(...)`로 승인 비교
- 승인 기준 파일은 ApprovalTests 표준 방식인 `tests/approval_tests/*.approved.txt`로 추가

추가된 승인 파일:
