1. 현재 `main()`에서 ECB 역할 혼재

현재 `main()` 자체는 비교적 얇습니다.

```190:206:cpp/UnitConverter.cpp
#ifndef UNIT_CONVERTER_TEST
int main() {
    resetDefaultUnits();
    std::cerr << "Insert value for converting (ex: meter:2.5): ";

    std::string input;
    std::getline(std::cin, input);

    try {
        std::cout << formatPlain(handleInput(input));
    } catch (const std::invalid_argument& error) {
        std::cerr << error.what() << std::endl;
        return 1;
    }

    return 0;
}
#endif
```

다만 `main()`이 호출하는 함수들이 모두 같은 파일에 있어 ECB 경계가 흐립니다.

| ECB 역할 | 현재 위치 | 문제 |
|---|---|---|
| Entity | `kMeterToFeet`, `kMeterToYard`, `unitRates()`, `ParsedInput`, `ConversionResult`, `BoundaryResult` | 변환 비율 데이터와 결과 데이터 구조가 한 파일 내부 익명 namespace에 섞여 있음 |
| Control | `convert()`, `convertAll()`, `handleInput()`, `resetDefaultUnits()`, `registerUnit()` | 변환 흐름과 단위 등록/초기화 책임이 분리되지 않음 |
| Boundary | `parseInput()`, `formatPlain()`, `formatJson()`, `loadConfig()`, `main()` | CLI 입력, 출력 포맷, 설정 파일 로딩이 변환 로직과 같은 파일에 있음 |

3. 새 단위 추가 시 변경 최소화 구조

추천 구조는 “단위 데이터는 Registry에 등록하고, 변환 로직은 Registry만 조회”하는 방식입니다.

```text
Entity
- Unit
- UnitRegistry
- ConversionResult

Control
- UnitConverterService
  - convert(from, value, to)
  - convertAll(from, value)

Boundary
- CliInputParser
- PlainOutputFormatter / JsonOutputFormatter
- ConfigLoader
- main.cpp
```

새 단위 추가 흐름은 이렇게 가져가면 됩니다.

```cpp
registry.registerUnit("inch", 0.0254);
converter.convert("inch", 10.0, "meter");
```

이 구조에서는 `inch`, `mile`, `cubit` 같은 새 단위를 추가할 때 변환 공식이나 `if-else` 코드를 수정하지 않고, `UnitRegistry`에 단위명과 meter 기준 비율만 추가하면 됩니다.
