## 3. 테스트 샘플 선정

대표 샘플은 `meter -> feet` 변환으로 선정했다.

| 항목 | 내용 |
|---|---|
| 선택 기능 | `meter -> feet` 변환 |
| 입력 예시 | `meter:2.5` |
| 기대 출력 | `2.5 meter = 8.202100 feet` |
| 선택 이유 | README와 PRD의 핵심 비율 `1 meter = 3.28084 feet`를 직접 검증할 수 있음 |
| 확장성 | `meter:0`, 매우 큰 수, 소수 6자리, 형식 오류, 미지원 단위까지 같은 테스트 축으로 확장 가능 |

## 6. Catch2 RED 테스트 스켈레톤

현재 `tests/test_unit_converter_red.cpp`는 RED 원칙에 맞춰 구현 호출 없이 테스트 이름과 태그만 정의하고, 본문은 모두 `FAIL("RED");` 한 줄로 구성했다.

### 6.1 Boundary 테스트 스켈레톤

| 테스트 이름 | 태그 | 보호 계약 |
|---|---|---|
| `parse_meter_input_returns_conversion_result` | `[boundary]` | 정상 입력 변환 결과 반환 |
| `parse_missing_colon_throws_invalid_argument` | `[boundary]` | `unit:value` 형식 계약 |
| `parse_negative_value_throws_invalid_argument` | `[boundary]` | 길이 값은 0 이상 |
| `parse_unknown_unit_throws_invalid_argument` | `[boundary]` | 등록 단위만 변환 허용 |
| `format_plain_output_preserves_source_unit_and_value` | `[boundary]` | 원 입력 단위·값 보존 |
| `format_json_output_returns_expected_schema` | `[boundary]` | JSON 출력 스키마 고정 |

### 6.2 Domain 테스트 스켈레톤

| 테스트 이름 | 태그 | 보호 계약 |

| `convert_meter_to_yard_returns_correct_ratio` | `[domain]` | `1 meter = 1.09361 yard` |
| `convert_yard_to_meter_returns_inverse_ratio` | `[domain]` | yard 역변환 |

| `register_unit_enables_new_unit_conversion` | `[domain]` | 동적 단위 등록 |

## 7. 결함 분석 요약

`docs/defect_list.md`에는 현재 구현과 요구 계약 간 차이를 결함으로 정리했다.

| Severity | 건수 | 대표 결함 |
|---|---:|---|
| Critical | 2 | 음수 입력이 변환됨, 콜론 2개 이상 입력이 일부 파싱될 수 있음 |
| Major | 6 | 예외 정책 불일치, 오버플로 방어 없음, 동적 등록/설정 로드 미구현 |
| Minor | 4 | 출력 정밀도 및 원 입력 값 표시 포맷 불일치 |

### 7.1 우선 수정 순서

1. 입력 검증 Critical 결함 차단: 음수, 콜론 개수 오류
2. 실패 정책 정리: `std::invalid_argument` 기반 예외 계약
3. 출력 포맷 정리: 6자리 고정 소수, 원 입력 보존
4. 확장 기능 구현: 동적 등록, JSON/YAML 설정 로드

## 8. 빌드 검증 상태

현재 단계에서는 구현을 수정하지 않고 RED 테스트 스켈레톤만 컴파일 가능하도록 구성했다.

| 명령 | 결과 |
|---|---|
| `cmake -S . -B build` | 통과 |
| `cmake --build build` | 통과 |
| RED 테스트 실행 | 의도적으로 실패해야 함 |

주의할 점은 빌드 통과가 기능 통과를 의미하지 않는다는 것이다. RED 테스트는 `FAIL("RED");`로 고정되어 있으므로 테스트 실행 시 실패하는 것이 현재 단계의 정상 상태다.
