# UnitConverter_05 보너스 감쇠 단위 변환 보고서

## 1. 개요

본 보고서는 `UnitConverter_05` 프로젝트에서 수행한 신규 보너스 기능 `registerUnit("cubit", 0.4572)` 기반 단위 등록 및 변환 작업 결과를 정리한다.

작업은 TDD 흐름에 따라 RED 테스트 작성, GREEN 최소 구현, 전체 테스트와 Golden Master, 커버리지 확인 순서로 진행했다. REFACTOR 단계는 수행하지 않았다.

## 3. 요구사항

신규 기능은 동적 단위 등록 후 meter를 허브로 사용하여 변환하는 계약을 검증한다.

| ID | 검증 내용 | 기대 결과 |
|---|---|---|
| BT-01 | `registerUnit("cubit", 0.4572)` 후 `cubit -> meter` | `0.4572` |
| BT-02 | 등록 후 `meter -> cubit` 역변환 | `1.0 / 0.4572` |
| BT-03 | 등록 후 `cubit -> feet` 교차 변환 | `0.4572 * 3.28084` |
| BT-04 | 음수 비율 등록 | `std::invalid_argument` |
| BT-05 | 등록 후 `convertAll("cubit", 1.0)` | 전체 대상 단위 반환 |
| BT-06 | 기존 `meter -> feet` 회귀 보호 | `3.28084` 유지 |

허용 오차는 모든 실수 비교에서 `1e-5`를 사용했다.

## 4. RED 단계

먼저 `src/DecayingUnit.cpp`에는 API 선언만 두고 `tests/test_decaying_unit.cpp`에서 BT-01~06을 작성했다.

실행 명령:

```powershell
cmake --build build
ctest --test-dir build
```

확인 결과:

```text

test_decaying_unit.obj : error LNK2019: registerUnit unresolved external
test_decaying_unit.obj : error LNK2019: convert unresolved external
test_decaying_unit.obj : error LNK2019: convertAll unresolved external
```

신규 BT 테스트가 미구현 API 때문에 실패하는 RED 상태를 확인했다.

## 5. GREEN 최소 구현

`src/DecayingUnit.cpp`에 다음 최소 구현만 추가했다.

| 기능 | 구현 내용 |
|---|---|
| 내부 Registry | `std::map<std::string, double>` 기반 단위명/미터 기준 비율 저장 |
| 기본 단위 | `meter`, `feet`, `yard` 기본 비율 등록 |
| `registerUnit()` | 비율이 `0` 이하이면 `std::invalid_argument` 발생, 정상 비율은 Registry 저장 |
| `convert()` | `fromUnit -> meter -> toUnit` 허브 경유 변환 |
| `convertAll()` | 현재 등록된 모든 단위 중 source 단위를 제외하고 변환 결과 반환 |

기존 `cpp/UnitConverter.cpp`의 `Item` 구조체와 기존 변환 로직은 수정하지 않았다.

## 9. 실행 환경 특이사항

Windows PowerShell 환경에서 `&&` 체인이 파싱되지 않아 실제 실행은 세미콜론과 `$LASTEXITCODE` 확인 방식으로 순차 수행했다.

또한 Visual Studio multi-config 빌드에서는 `ctest --test-dir build` 단독 실행 시 `Missing "-C <config>"?`로 테스트가 `Not Run` 처리된다. 따라서 실제 판정은 `ctest --test-dir build -C Debug`로 수행했다.
