# Product Requirements Document: UnitConverter_05

## 1. 프로젝트 개요

### 1.1 한 줄 목적문

UnitConverter_05는 C++/클린 아키텍처 학습자가 길이 단위 변환 문제를 통해 계약 정의, 테스트 우선 검증, 레이어 분리를 학습하기 위한 C++17 기반 단위 변환 학습 시스템이다.

### 1.2 배경 및 문제 정의

학습자는 meter, feet, yard 간 길이 변환 요구사항을 처음에는 단순 계산 문제로 인식하기 쉽다. 그러나 이 저장소의 핵심 문제는 변환 알고리즘 자체가 아니라 입력 형식, 오류 정책, 기준 비율, 출력 표현, 단위 확장 방식을 테스트 가능한 계약으로 고정하는 것이다. 현재 요구사항은 기본 단위 변환, 입력 검증, OCP/SRP, 설정 외부화, 동적 단위 등록, 출력 포맷 선택을 함께 다루므로 Boundary, Control, Entity 책임 분리가 필요하다. 따라서 이 PRD는 구현 전에 무엇을 성공으로 볼지, 어떤 실패를 어떻게 반환할지, 어떤 계약을 회귀로 보호할지를 명시한다.

### 1.3 목표

- Domain 테스트는 라인 커버리지 90% 이상, 분기 커버리지 85% 이상을 달성한다.
- Boundary 계약 테스트는 입력 오류, 출력 포맷, 에러 스키마 항목을 모두 검증한다.
- Data 실패 테스트는 설정 파일 없음, 설정 형식 오류, 중복 단위, 잘못된 비율을 포함한다.
- `1 meter = 3.28084 feet`, `1 meter = 1.09361 yard` 기준 비율은 회귀 테스트로 보호한다.
- 새 단위 추가 후 기존 meter, feet, yard 변환 테스트는 수정 없이 통과한다.
- 동일 입력, 동일 단위 등록 상태, 동일 출력 포맷은 항상 동일한 결과를 생성한다.

### 1.4 비목표(Non-Goal)

- 이 프로젝트는 모든 물리 단위 변환을 지원하지 않는다.
- 이 프로젝트는 GUI 애플리케이션을 제공하지 않는다.
- 이 프로젝트는 네트워크 서비스, 데이터베이스 저장, 사용자 계정 관리를 포함하지 않는다.

| 기능 | 입력 계약 | 출력 계약 | 실패 계약 |

| 동적 등록 | `register:<unit>=<rateToMeter>` | 등록 성공 상태와 갱신된 단위 목록 | `INVALID_UNIT_NAME`, `INVALID_RATE`, `DUPLICATE_UNIT` |
| 출력 포맷 선택 | 출력 포맷명 `plain`, `json`, `csv`, `table` | 선택 포맷에 맞는 동일 의미의 변환 결과 | `UNSUPPORTED_OUTPUT_FORMAT` |

### 3.3 제약 사항

- Phase 4 Gherkin Background와 동일하게 기준 단위는 `meter`이다.
- Phase 4 Gherkin Background와 동일하게 기본 등록 단위는 `meter`, `feet`, `yard`이다.
- Phase 4 Gherkin Background와 동일하게 `1 meter = 3.28084 feet`를 기준 비율로 사용한다.
- Phase 4 Gherkin Background와 동일하게 `1 meter = 1.09361 yard`를 기준 비율로 사용한다.
- feet와 yard 간 변환은 meter 기준 비율을 경유해 계산한다.
- 기본 입력 형식은 `unit:value`이다.
- 콜론이 없거나 콜론이 2개 이상이면 `INVALID_FORMAT`으로 실패한다.
- 단위명이 비어 있으면 `INVALID_UNIT_NAME`으로 실패한다.
- 값이 비어 있으면 `INVALID_VALUE`로 실패한다.
- 단위명은 소문자 영문으로 시작하고 소문자 영문, 숫자, 밑줄만 포함한다.
- 값은 십진수 숫자여야 한다.
- 길이 값은 0 이상이어야 한다.
- 음수 입력은 변환 전에 `NEGATIVE_VALUE`로 실패한다.
- 미지원 단위는 변환 전에 `UNKNOWN_UNIT`으로 실패한다.
- 잘못된 소수 형식은 `INVALID_VALUE`로 실패한다.
- `meter:0`, `feet:0`, `yard:0`은 유효 입력이며 모든 변환 결과 값은 0이다.
- 동일 입력과 동일 등록 상태는 반복 실행해도 동일한 변환값과 동일한 대상 단위 순서를 반환한다.

## 4. 비기능 요구사항

### 4.1 기술 스택

| 항목 | 기준 |
|---|---|
| 언어 표준 | C++17 |
| 빌드 시스템 | CMake |
| 테스트 프레임워크 | Catch2 |

### 4.2 아키텍처 원칙

- OCP: 새 단위 추가가 기존 변환 계산 규칙 수정을 요구하지 않아야 한다.
- SRP: 입력 파싱, 유스케이스 조정, 변환 규칙, 설정 로드, 출력 직렬화 책임은 분리되어야 한다.
- BCE: Boundary는 외부 입력과 출력 계약을 담당한다.
- BCE: Control은 유스케이스 흐름과 의존성 연결을 담당한다.
- BCE: Entity는 단위, 측정값, 비율, 레지스트리, 변환 규칙을 담당한다.
- 의존성 방향은 `Boundary -> Control -> Entity`를 따른다.
- Entity는 Boundary 출력 포맷과 Data 저장소 구현에 의존하지 않는다.
- Control은 Data 인터페이스에 의존하고 구체 저장소 구현에 의존하지 않는다.

### 4.3 테스트 커버리지 목표

| 영역 | 커버리지 목표 |
|---|---|
| Domain | 라인 90% 이상, 분기 85% 이상 |
| Boundary | 라인 85% 이상, 오류 분기 90% 이상 |
| Data | 라인 80% 이상, 실패 케이스 90% 이상 |
| Integration | 정상 시나리오 3개 이상, 실패 시나리오 5개 이상 |

### 4.4 확장성 원칙

- 새 단위는 단위명과 meter 기준 비율로 등록되어야 한다.
- 새 단위 등록은 기존 meter, feet, yard 기준 비율을 변경하지 않아야 한다.
- 출력 포맷 추가는 변환 계산 규칙을 변경하지 않아야 한다.
- 설정 저장소 변경은 Entity 변환 규칙을 변경하지 않아야 한다.
- 동적 등록 실패는 기존 등록 단위 목록을 변경하지 않아야 한다.

## 5. 데이터 요구사항

### 5.1 단위 비율 상수

| 단위 | meter 기준 비율 | 검증 기준 |
|---|---:|---|
| meter | 1.0 | 기준 단위로 고정 |
| feet | 0.3047999902464003 | `1 meter = 3.28084 feet`와 역관계 |
| yard | 0.9144027578387177 | `1 meter = 1.09361 yard`와 역관계 |

### 5.2 설정 외부화 방식

| 방식 | 용도 | 통과 기준 |
|---|---|---|
| 메모리 기본값 | 기본 meter, feet, yard 단위 제공 | 설정 파일 없이도 기본 단위 3개가 등록된다. |
| JSON 설정 | 권장 외부 설정 형식 | 단위명과 meter 기준 비율을 로드할 수 있다. |
| YAML 설정 | 선택 외부 설정 형식 | JSON과 동일한 필드 의미를 가진다. |

설정 데이터는 단위명과 `rateToMeter`를 포함해야 한다. `meter`의 `rateToMeter`는 `1.0`이어야 한다. 중복 단위명, 누락 필드, 0 이하 비율, 파싱 불가 형식은 로드 실패로 처리한다.

### 5.3 동적 단위 등록 계약

| 항목 | 계약 |
|---|---|
| 입력 형식 | `register:<unit>=<rateToMeter>` |
| 단위명 규칙 | 소문자 영문으로 시작하고 소문자 영문, 숫자, 밑줄만 포함 |
| 비율 규칙 | `rateToMeter > 0` |
| 성공 결과 | 새 단위가 이후 변환 대상 목록에 포함된다. |
| 실패 결과 | 잘못된 단위명은 `INVALID_UNIT_NAME`, 0 이하 비율은 `INVALID_RATE`, 중복 단위는 `DUPLICATE_UNIT`으로 실패한다. |

## 6. 출력 요구사항

### 6.1 콘솔 기본 포맷

| 항목 | 계약 |
|---|---|
| 포맷명 | `plain` |
| 행 순서 | 등록 단위 순서에서 입력 단위를 제외한 순서 |
| 행 형식 | `<sourceValue> <sourceUnit> = <convertedValue> <targetUnit>` |
| 원 입력 보존 | 모든 행은 원 입력 값과 원 입력 단위를 포함한다. |
| 소수 자릿수 | 기본 표시 정밀도는 소수점 1자리이며, 정확도 검증은 표시 문자열이 아니라 내부 변환값으로 수행한다. |
| 내부 검증 정밀도 | 변환값은 허용 오차 `0.00001` 이내로 검증 가능해야 한다. |

### 6.2 JSON 출력 스키마

| 필드 | 필수 여부 | 의미 |
|---|---|---|
| `sourceUnit` | 필수 | 원 입력 단위 |
| `sourceValue` | 필수 | 원 입력 값 |
| `results` | 필수 | 변환 결과 목록 |
| `results[].targetUnit` | 필수 | 대상 단위 |
| `results[].convertedValue` | 필수 | 변환된 숫자 값 |
| `results[].displayText` | 필수 | 사용자 표시 문자열 |

JSON 실패 응답은 `errorCode`, `message`, `field`, `input`을 포함한다.

### 6.3 CSV 출력 스키마

| 순서 | 컬럼명 | 의미 |
|---:|---|---|
| 1 | `sourceUnit` | 원 입력 단위 |
| 2 | `sourceValue` | 원 입력 값 |
| 3 | `targetUnit` | 대상 단위 |
| 4 | `convertedValue` | 변환된 숫자 값 |

CSV 출력은 첫 줄에 고정 헤더를 포함한다. 변환 결과 1개는 CSV 데이터 행 1개로 표현한다.

### 6.4 표(Table) 출력 스키마

| 순서 | 열 이름 | 의미 |
|---:|---|---|
| 1 | `Source` | 원 입력 단위 |
| 2 | `Value` | 원 입력 값 |
| 3 | `Target` | 대상 단위 |
| 4 | `Converted` | 변환된 표시 값 |

표 출력은 변환 결과 1개를 본문 행 1개로 표현한다. 표 출력의 행 수는 변환 결과 수와 같아야 한다.

## 7. 성공 지표

### 7.1 인수 기준

- [ ] `meter:1` 입력의 feet 결과가 `3.28084`와 허용 오차 `0.00001` 이내이다.
- [ ] `meter:1` 입력의 yard 결과가 `1.09361`과 허용 오차 `0.00001` 이내이다.
- [ ] `feet:3.28084` 입력의 meter 결과가 `1.0`과 허용 오차 `0.00001` 이내이다.
- [ ] `yard:1.09361` 입력의 meter 결과가 `1.0`과 허용 오차 `0.00001` 이내이다.
- [ ] `yard:-1` 입력은 변환 전에 `NEGATIVE_VALUE`로 실패하고 변환 결과를 생성하지 않는다.
- [ ] `inch:1` 입력은 `UNKNOWN_UNIT`으로 실패하고 변환 결과를 생성하지 않는다.
- [ ] JSON, CSV, 표 출력은 원 입력 단위와 원 입력 값을 보존한다.
- [ ] JSON, CSV, 표 출력은 동일 입력에 대해 동일한 변환 결과 수를 표현한다.
- [ ] 설정 형식 오류는 `DATA_PARSE_ERROR`로 실패하고 변환을 실행하지 않는다.
- [ ] 새 단위 등록 후 기존 meter, feet, yard 변환 테스트는 수정 없이 통과한다.
- [ ] 동일 입력, 동일 등록 상태, 동일 출력 포맷을 2회 실행하면 대상 단위 순서와 변환값이 동일하다.

### 7.2 회귀 보호 규칙

- README 기준 비율 `1 meter = 3.28084 feet`는 변경 금지 계약으로 테스트한다.
- README 기준 비율 `1 meter = 1.09361 yard`는 변경 금지 계약으로 테스트한다.
- `INVALID_FORMAT`, `INVALID_UNIT_NAME`, `INVALID_VALUE`, `NEGATIVE_VALUE`, `UNKNOWN_UNIT`, `DATA_PARSE_ERROR` 오류 코드는 문자열 변경을 회귀로 간주한다.
- JSON 필드명 `sourceUnit`, `sourceValue`, `results`, `targetUnit`, `convertedValue`, `displayText` 변경은 회귀로 간주한다.
- CSV 헤더 `sourceUnit,sourceValue,targetUnit,convertedValue` 변경은 회귀로 간주한다.
- 표 열 이름 `Source`, `Value`, `Target`, `Converted` 변경은 회귀로 간주한다.
- 새 출력 포맷 추가는 기존 plain, JSON, CSV, 표 출력 계약을 변경하지 않아야 한다.

## 8. 용어 정의

| 용어 | 정의 |
|---|---|
| 기준 단위 | 모든 변환이 경유하는 중심 단위이며 이 프로젝트에서는 `meter`이다. |
| 등록 단위 | 변환에 사용할 수 있도록 단위명과 meter 기준 비율이 등록된 단위이다. |
| 측정값 | 숫자 값과 단위명이 결합된 길이 입력이다. |
| 변환 비율 | 특정 단위 1개가 meter로 환산되는 값이다. |
| Boundary | 사용자 입력 파싱, 출력 직렬화, 외부 오류 메시지를 담당하는 레이어이다. |
| Control | 입력 요청을 유스케이스 흐름으로 조정하고 Entity와 Data 인터페이스를 연결하는 레이어이다. |
| Entity | 단위, 측정값, 비율, 레지스트리, 변환 규칙을 보유하는 도메인 레이어이다. |
| 계약 테스트 | 입력, 출력, 오류 스키마처럼 외부에서 관찰 가능한 동작을 고정하는 테스트이다. |
| 회귀 보호 | 기준 비율, 오류 코드, 출력 스키마가 변경될 때 테스트 실패로 감지하는 정책이다. |
| 동적 단위 등록 | 실행 중 새 단위명과 meter 기준 비율을 추가하는 기능이다. |
